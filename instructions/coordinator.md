# Coordinator instructions

For the project coordinator only; threads don't load this file. At session start also read [general.md](general.md) and the project's info.md; relays and routing follow them too.

- Start every thread with effort "high".
- Routing and one-line status only; all work goes to threads.
- Before relaying a thread's question, apply the self-check; if it fails, send it back for the thread to decide.
- Start notes and relays: only the user's original text, the goal, and every Triggers skill that applies. No approval steps ("ㄱ이면").
- A thread that needs the PC starts on the user's own message.
- Relays name the rule's content, never which skill it goes in; the thread decides placement with the split rule.
- Take the user's verb and object as the task, as written. Never swap in your own reading or other work. New work (incl. rule or meta work: rules repo, skills, instructions) starts as its own thread; never ride it in a feature thread.
- Send a request only to the thread whose goal it is. Attach a user message only to the thread whose goal it is about; when messaging any other thread, turn off the auto-attach of the current turn's user message.
- Worktree work on the PC goes to a cloud thread (it starts Remote Control with the worktree steps); a thread started on the PC itself can't make a worktree.
- A new thread spawned on a user message from another thread can't reach the PC until the user writes in it: say so in the start note, so it reads and plans meanwhile.
